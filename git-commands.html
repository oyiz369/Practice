Everyday commands you reach for constantly, and the sharper tools you pull out when something has gone sideways. Every entry ships with copy-ready usage samples.

Frequently Used Commands

Daily driver

The core loop: get a repo, see what changed, stage it, commit it, sync it.

git init

Create a brand-new repository in the current directory.

# start tracking the folder you are standing in
git init

# create the folder and initialize it in one step
git init my-project

# initialize with "main" as the default branch name
git init -b main

git clone

Copy an existing remote repository, with its full history, onto your machine.

git clone https://github.com/user/repo.git

# clone into a differently named folder
git clone https://github.com/user/repo.git my-folder

# only the latest commit — much faster for big repos
git clone --depth 1 https://github.com/user/repo.git

# clone a specific branch only
git clone -b develop --single-branch https://github.com/user/repo.git

git config

Set your identity and preferences. Do this once per machine before your first commit.

# identity used on every commit you author (--global = all repos)
git config --global user.name "Temitope Joseph"
git config --global user.email "you@example.com"

# override identity for just this one repo (omit --global)
git config user.email "work@company.com"

# handy defaults
git config --global init.defaultBranch main
git config --global pull.rebase true
git config --global core.editor "code --wait"

# make an alias: `git lg` for a pretty log
git config --global alias.lg "log --oneline --graph --decorate --all"

# inspect what is currently set, and where it came from
git config --list --show-origin
git config user.email

git status

Show which files are staged, modified, or untracked. Run it constantly — it is free.

git status

# compact one-line-per-file output
git status -s

# short output plus the current branch line
git status -sb

# include files hidden by .gitignore
git status --ignored

git add

Stage changes for the next commit.

# one file
git add index.html

# everything in the current directory and below
git add .

# every change in the repo, wherever you are standing
git add -A

# only files git already tracks (skips new/untracked files)
git add -u

# pattern match
git add "*.css"

# choose hunk by hunk what to stage — the best way to split a messy edit
git add -p

git commit

Record the staged snapshot into history with a message.

git commit -m "Add login form validation"

# multi-line message: subject, blank line, body
git commit -m "Fix cart total rounding" -m "Prices were floored instead of rounded to 2dp."

# stage all tracked modifications and commit in one shot
git commit -am "Tweak footer spacing"

# redo the last commit — fix the message or add forgotten files
git add forgotten-file.js
git commit --amend -m "Add login form validation"

# amend without opening an editor or changing the message
git commit --amend --no-edit

git diff

See the actual line-by-line changes, before or after staging.

# unstaged changes (working tree vs. staging area)
git diff

# staged changes — exactly what a commit would capture
git diff --staged

# limit to one file or folder
git diff src/app.js

# compare two branches
git diff main..feature-login

# just the file names, or just the counts
git diff --name-only
git diff --stat

# highlight moved words instead of whole lines
git diff --word-diff

git log

Browse the commit history, filtered any way you like.

git log

# the readable everyday view
git log --oneline --graph --decorate --all

# last 5 commits with the patch for each
git log -5 -p

# who changed what, and how much
git log --stat
git log --author="Temitope"

# by time or by message content
git log --since="2 weeks ago" --until="yesterday"
git log --grep="checkout bug"

# every commit that touched one file, following renames
git log --follow -- src/utils/date.js

# custom format
git log --pretty=format:"%h %an %ar - %s"

git branch

List, create, rename, and delete branches.

git branch                 # local branches, * marks current
git branch -a              # local + remote-tracking
git branch -vv             # with last commit and upstream

git branch feature-signup  # create (does not switch)
git branch -m new-name     # rename current branch

git branch -d old-feature  # delete (refuses if unmerged)
git branch -D old-feature  # force delete

# which branches are already merged into main?
git branch --merged main

git switch / git checkout

Move between branches. switch is the modern, clearer verb; checkout still works everywhere.

git switch main
git switch -c feature-signup      # create and switch
git switch -                      # jump back to previous branch

# track a branch that exists only on the remote
git switch -c hotfix origin/hotfix

# the older equivalents
git checkout main
git checkout -b feature-signup

# inspect an old commit without changing any branch (detached HEAD)
git checkout a1b2c3d

git restore

Throw away local edits or unstage files, without touching your branch pointers.

# discard unstaged edits to a file — NOT undoable
git restore index.html

# discard everything unstaged
git restore .

# unstage a file but keep the edits
git restore --staged index.html

# pull a file back as it was in another commit or branch
git restore --source=HEAD~3 src/app.js
git restore --source=main config.json

git pull

Fetch from the remote and integrate into your current branch.

git pull

# explicit remote and branch
git pull origin main

# rebase your local commits on top instead of creating a merge commit
git pull --rebase

# refuse to create a merge commit — fail instead if histories diverged
git pull --ff-only

git push

Send your commits to the remote.

git push

# first push of a new branch — sets the upstream so plain `git push` works after
git push -u origin feature-signup

# push tags
git push origin v1.2.0
git push --tags

# delete a remote branch
git push origin --delete old-feature

# after a rebase/amend: safe force — aborts if someone else pushed meanwhile
git push --force-with-lease

git fetch

Download remote changes without touching your working tree. The safe way to look before you leap.

git fetch
git fetch origin main

# update everything and delete stale remote-tracking branches
git fetch --all --prune

# see what arrived before merging it
git fetch
git log HEAD..origin/main --oneline

git merge

Join another branch's history into your current branch.

git switch main
git merge feature-signup

# always create a merge commit, even when a fast-forward is possible
git merge --no-ff feature-signup

# collapse the whole branch into one staged change to commit yourself
git merge --squash feature-signup
git commit -m "Add signup flow"

# conflicts: fix the files, then
git add resolved-file.js
git merge --continue

# or back out entirely
git merge --abort

git remote

Manage the named URLs your repo talks to.

git remote -v                                    # list with URLs
git remote add origin git@github.com:user/repo.git
git remote set-url origin git@github.com:user/new.git
git remote rename origin upstream
git remote remove upstream
git remote show origin                           # detailed state

# drop remote-tracking branches that no longer exist upstream
git remote prune origin

git stash

Park unfinished work on a shelf so you can switch context, then bring it back.

git stash                                # shelve tracked modifications
git stash push -m "half-done navbar"     # with a label
git stash -u                             # include untracked files

git stash list                           # stash@{0}, stash@{1}, …
git stash show -p stash@{0}              # preview the diff

git stash pop                            # restore newest and remove it
git stash apply stash@{2}                # restore but keep the entry
git stash drop stash@{0}
git stash clear                          # delete all stashes

git tag

Mark a commit permanently — almost always a release.

git tag                                   # list
git tag v1.0.0                            # lightweight
git tag -a v1.0.0 -m "First release"      # annotated (preferred)

# tag a commit from the past
git tag -a v0.9.0 a1b2c3d -m "Beta"

git push origin v1.0.0
git tag -d v1.0.0                         # delete locally
git push origin --delete v1.0.0           # delete on the remote

git rm / git mv

Delete or rename files so git records the change properly.

git rm secret.txt                 # delete from disk and stage it
git rm --cached secret.txt        # stop tracking, keep the file on disk
git rm -r build/                  # recursive

git mv old-name.js new-name.js    # rename + stage in one move

git show

Inspect a single commit, tag, or file version.

git show                          # the most recent commit
git show a1b2c3d
git show HEAD~2                   # two commits back
git show v1.0.0

# a file exactly as it looked in some commit
git show HEAD~3:src/app.js

# names only
git show --stat a1b2c3d

Advanced Commands

Rewrite & rescue

History surgery, forensic tools, and escape hatches. Several of these rewrite commits — avoid rewriting anything already pushed to a shared branch.

git rebase

Replay your commits on top of another branch to keep history linear.

# move your feature branch onto the latest main
git switch feature-signup
git rebase main

# conflicts: fix files, stage, continue
git add resolved.js
git rebase --continue
git rebase --skip
git rebase --abort            # bail out, nothing lost

# rebase onto a different base entirely
git rebase --onto main develop feature-signup

# auto-apply fixup!/squash! commits during an interactive rebase
git rebase -i --autosquash main

git rebase -i (interactive)

Rewrite the last N commits — reorder, reword, squash, split, or drop them.

# edit the last 4 commits
git rebase -i HEAD~4

# the editor opens a to-do list; change the verb on each line:
#   pick   a1b2c3d Add signup form      <- keep as is
#   reword b2c3d4e Fx typo             <- keep, edit message
#   squash c3d4e5f Fix typo again      <- fold into the commit above
#   fixup  d4e5f6a More fixes          <- fold in, discard its message
#   edit   e5f6a7b Big commit          <- stop here so you can amend/split
#   drop   f6a7b8c Debug logging       <- delete the commit

# at an `edit` stop: change things, then
git commit --amend
git rebase --continue

# everything since branching off main
git rebase -i main

git cherry-pick

Copy specific commits from one branch onto another.

git cherry-pick a1b2c3d

# several at once, or an inclusive range
git cherry-pick a1b2c3d e5f6a7b
git cherry-pick a1b2c3d^..e5f6a7b

# apply the change but let you commit it yourself
git cherry-pick -n a1b2c3d

# append "(cherry picked from …)" to the message
git cherry-pick -x a1b2c3d

git cherry-pick --continue
git cherry-pick --abort

git reset

Move the branch pointer backwards. The mode decides what happens to your files.

# undo the last commit, keep changes staged
git reset --soft HEAD~1

# undo the last commit, keep changes unstaged (the default)
git reset --mixed HEAD~1
git reset HEAD~1

# undo the last commit AND destroy the changes — irreversible
git reset --hard HEAD~1

# unstage everything, keep edits
git reset

# throw away local commits and match the remote exactly
git fetch origin
git reset --hard origin/main

git revert

Undo a commit by adding a new inverse commit. Safe on shared branches, unlike reset.

git revert a1b2c3d

# revert several, oldest first
git revert a1b2c3d e5f6a7b

# stage the inverse without committing yet
git revert -n a1b2c3d

# reverting a merge: -m 1 keeps the first parent (usually main)
git revert -m 1 <merge-sha>

git reflog

Git's black box recorder — every position HEAD has held. This is how you recover "lost" commits after a bad reset or rebase.

git reflog

# typical output
#   a1b2c3d HEAD@{0}: reset: moving to HEAD~3
#   e5f6a7b HEAD@{1}: commit: Add payment module   <- the work you thought was gone

# get it back
git reset --hard HEAD@{1}

# or park it on a rescue branch instead
git branch recovered e5f6a7b

# reflog for one branch
git reflog show feature-signup

git bisect

Binary-search the history to find the exact commit that introduced a bug.

git bisect start
git bisect bad                 # current commit is broken
git bisect good v1.0.0         # this old tag was fine

# git checks out a midpoint; test it, then say which it is
git bisect good
git bisect bad

# …repeat until git prints "<sha> is the first bad commit"
git bisect reset               # return to where you started

# fully automatic: a script exiting non-zero marks a commit bad
git bisect start HEAD v1.0.0
git bisect run npm test

git blame

Show who last changed each line, and in which commit.

git blame src/app.js

# only lines 40–60
git blame -L 40,60 src/app.js

# see past pure whitespace/formatting churn
git blame -w src/app.js

# follow lines through moves and copies to the real author
git blame -w -C -C -M src/app.js

# blame the file as it was before a given commit
git blame a1b2c3d^ -- src/app.js

git worktree

Check out several branches into separate folders from one repo — no stashing, no re-cloning.

# open an existing branch in a sibling directory
git worktree add ../hotfix-tree hotfix

# create a new branch and a worktree for it at once
git worktree add -b review-pr ../review-tree origin/feature-x

git worktree list
git worktree remove ../hotfix-tree
git worktree prune              # clean up records of deleted folders

git submodule

Embed another repository inside yours at a pinned commit.

git submodule add https://github.com/user/lib.git vendor/lib

# after cloning a repo that has submodules
git submodule update --init --recursive

# or do it during the clone
git clone --recurse-submodules https://github.com/user/repo.git

# bump every submodule to its latest upstream commit
git submodule update --remote --merge

# run a command inside each one
git submodule foreach 'git switch main && git pull'

git clean

Delete untracked files. Destructive — always dry-run first.

git clean -n            # dry run: list what WOULD be deleted
git clean -f            # delete untracked files
git clean -fd           # files and directories
git clean -fdx          # also ignored files (node_modules, build/, .env!)
git clean -i            # interactive, choose item by item

git rev-parse / git describe

Resolve names to SHAs and give a commit a human-readable version label — the plumbing behind most scripts and CI pipelines.

git rev-parse HEAD                    # full SHA
git rev-parse --short HEAD            # abbreviated
git rev-parse --abbrev-ref HEAD       # current branch name
git rev-parse --show-toplevel         # repo root path

# "v1.2.0-14-ga1b2c3d" = 14 commits after tag v1.2.0
git describe --tags
git describe --tags --always --dirty

git format-patch / git am

Turn commits into .patch files and apply them elsewhere — email-style collaboration, no shared remote needed.

# export the last 3 commits as numbered patch files
git format-patch -3

# everything your branch adds over main, into ./patches
git format-patch main -o patches/

# on the other machine: apply them as real commits
git am patches/0001-Add-login.patch
git am patches/*.patch
git am --abort

# plain diff, applied without committing
git diff main > change.diff
git apply change.diff
git apply --check change.diff        # test first

git sparse-checkout

Work with only part of a huge monorepo on disk.

git clone --filter=blob:none --sparse https://github.com/user/monorepo.git
cd monorepo

git sparse-checkout set apps/web packages/ui
git sparse-checkout list
git sparse-checkout add packages/api
git sparse-checkout disable          # back to the full tree

git range-diff / git shortlog

Compare two versions of the same series, and summarize contributions.

# what actually changed between the old branch and the rebased one?
git range-diff main old-feature new-feature
git range-diff @{u}...HEAD           # before vs. after your rebase

# commits grouped by author, counts only
git shortlog -sn
git shortlog -sn --since="1 month ago"

git filter-repo

Rewrite entire history — strip a leaked secret or purge a huge file from every commit. Replaces the deprecated filter-branch. Requires a separate install, and rewrites every SHA.

# always work on a fresh clone
git clone --mirror https://github.com/user/repo.git
cd repo.git

# remove a file from all of history
git filter-repo --path .env --invert-paths
git filter-repo --path secrets/ --invert-paths

# keep only one subdirectory as the new repo root
git filter-repo --subdirectory-filter apps/web

# fix an email across every commit
git filter-repo --mailmap mailmap.txt

# then force-push, and tell every collaborator to re-clone
git push --force --all

git rerere

"Reuse recorded resolution" — git memorizes how you solved a conflict and replays it automatically next time. Invaluable on long-lived rebases.

git config --global rerere.enabled true

# resolve a conflict once as usual; git records it silently
# next time the same conflict appears it is resolved for you

git rerere status
git rerere diff
git rerere forget path/to/file.js    # drop a bad recorded resolution

git archive / git bundle

Export a snapshot without the .git folder, or pack a whole repo into one transferable file.

# zip/tarball of a tag or branch — clean release artifact
git archive --format=zip -o site-v1.0.zip v1.0.0
git archive HEAD | tar -x -C /var/www/deploy

# the entire repo as a single file you can email or copy to a USB stick
git bundle create repo.bundle --all
git clone repo.bundle restored-repo

# bundle only what is new since a tag
git bundle create update.bundle v1.0.0..main

git gc / git fsck / git count-objects

Maintenance: compact the object store, check integrity, find orphaned commits.

git gc                       # garbage collect and repack
git gc --aggressive --prune=now

git count-objects -vH        # how big is this repo, really?

git fsck                     # verify object integrity
git fsck --lost-found        # surface dangling commits/blobs

# commits with no branch pointing at them — reflog's last resort
git fsck --unreachable --no-reflogs

git hooks

Scripts git runs automatically at lifecycle points. They live in .git/hooks/ and are not committed unless you point git elsewhere.

ls .git/hooks/               # pre-commit, commit-msg, pre-push, …

# create a pre-commit hook that blocks a bad commit
cat > .git/hooks/pre-commit <<'EOF'
#!/bin/sh
npm run lint || exit 1
EOF
chmod +x .git/hooks/pre-commit

# share hooks with the team: commit them, then point git at the folder
git config core.hooksPath .githooks

# skip hooks for one commit
git commit --no-verify -m "WIP"

git notes / git replace

Attach metadata to existing commits, or substitute one object for another, without rewriting history.

git notes add -m "Reviewed by QA on 2026-08-12" a1b2c3d
git notes show a1b2c3d
git log --show-notes

# notes are not pushed by default
git push origin refs/notes/commits

# transparently swap one commit for another (grafts, history stitching)
git replace a1b2c3d e5f6a7b
git replace -l
git replace -d a1b2c3d
Tip: almost every command here has a manual page — git help rebase or git rebase --help. When something goes wrong, git reflog is usually the way back.
